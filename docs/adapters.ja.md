# ハーネス対応とアダプター

[English](adapters.md)

`skills/` の Markdown が受け入れ、操作権限、担当、レビュー予算、候補の証跡を定義します。Workflow Support はこの資産とホスト別手順を提供し、Native Automation は検証済みアダプターで強制します。各操作にはプロジェクトの指示と実効権限が適用されます。

| 操作 | アダプター契約 | Codex | OpenCode Workflow Support |
|---|---|---|---|
| 検出 | 同じ手順を導入・起動し、実際に読み込まれたパスを確認する | ネイティブスキルとプラグイン | OpenCode v2 の標準スキル探索 |
| ロール | 起動前にロール・モデル・推論強度・アクセスを確認する | エージェント TOML とモデル一覧 | ユーザー設定のモデル・推論強度 |
| 隔離 | レビューを読み取り専用とし、並行作業者ごとに書き込み範囲を分ける | ネイティブサンドボックス、別セッションと worktree | 直列実行。操作者が独立レビューの読み取り専用アクセスを確認 |
| 再開・停止 | 自動実行の停止と終了状態を確認し、証跡を残す | Go アダプターとネイティブ app-server | 操作者がセッションを管理 |
| 納品 | 承認範囲内で Git・PR 操作を行い、証跡を候補 SHA に結びつける | 明示的に承認された Go ワークフロー | 操作者が管理。ネイティブ判定スキーマや自動化は未対応 |

書き込みを隔離できない場合、並列性が任意で、かつ直列実行でも必須の権限と能力をすべて満たす場合に限り直列化します。必須能力を確認できなければ、該当作業を止め、確認済みの証跡と阻害要因を報告します。[Codex アダプター](codex.ja.md)、[OpenCode ガイド](opencode.ja.md)、[v0.3.0 の動作基準（英語）](behavior-v0.3.0.md)を参照してください。Claude Code、Grok Build などは未対応です。

納品候補には基点 SHA、候補 SHA、各ゲートのコマンドと結果、レビュアーとレビュー済み SHA、残る制約を記録します。PR head と検証済みのローカル SHA が一致することを確認します。head が変わった場合は影響する振る舞いを再検証します。コミット、フィーチャーブランチへの push、PR 作成、個別承認が必要な操作はリポジトリとホストの規則に従います。

Go の `HarnessAdapter` と `GateRunner` は事前検証、品質ゲートとターン実行を定義します。選択モデルと権限、読み取り専用の独立レビュー、終了証跡とネイティブスキーマを確立できない場合は失敗します。Git 操作、候補への証跡の紐づけ、レビュー予算、承認済みの納品は Go Core が管理します。Codex アダプターはネイティブ app-server を使います。Go の契約テストは、[v0.3.0 の動作記録](behavior-v0.3.0.md)と [v0.4.0 タグの比較テスト](https://github.com/natori-hrj/nstack/tree/v0.4.0/tests)を基準にしています。
